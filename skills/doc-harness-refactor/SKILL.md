# doc-harness-refactor

重构文档类 Harness 结构，使其回归三个原则的健康状态。

## 理论基础

阅读 `references/doc-harness-theory.md`，其中定义了：

- **三个原则**：信息增量、最小编码、无法替代
- **三个功能**：记忆、约束、方向
- **地图角色**：AGENTS.md 作为中心索引，companion 文件承载细则
- **生命周期模型**：init → append → refactor → harden → (循环)

后续所有操作基于这些理论基础。重构目标并非"文档更少"或"文档更多"，而是让每个字节都通过三原则检验。

## Phase 0：前置检查

1. 检查 `.agents/AGENTS.md` 是否存在
2. 不存在 → "没有 AGENTS.md，无法重构空文档。请先用 `/doc-harness-init` 创建。"
3. 存在 → 读取 AGENTS.md 获取文档地图，找出所有引用的 companion 文件列表

## Phase 1：审计现状

### Step 1：读取全部文档

- 读取 AGENTS.md（地图），记录行数和段落结构
- 读取地图引用的所有 companion 文件
- 检查 `.claude/CLAUDE.md -> .agents/AGENTS.md` 软链接状态

### Step 2：逐文件三原则评估

对每个文件依次回答以下问题：

**信息增量** — 这段内容是否无法从代码、package.json、README、lint 规则、CI 配置中直接推导？
- 能直接从代码推导？→ 可删除
- 在多个文件中重复出现？→ 需合并，只留一处
- 引用了不存在的文件或命令？→ 过期，可删除

**最小编码** — 当前表达是否已是最精简的 actionable 形式？
- 能用一句话说清的段落写了三句？→ 可压缩
- 存在冗余模板化语言（如"请注意""另外需要说明的是"）？→ 可精简
- 大段列表可被表格、映射、结构化模式浓缩？→ 可重构

**无法替代** — 这段约束是否被其他已有 harness 覆盖？
- 和 git hook / linter / CI 检查规则重复？→ 删除（由机器执行）
- 标注了 TODO(harden) 的约束已稳定且已硬化？→ 准备删除
- TODO(harden) 尚未硬化？→ 保留不动

### Step 3：文档结构评估

- AGENTS.md 超过 150 行？→ 建议将细则拆分到 companion 文件
- 同一 companion 文件含多个不相关主题？→ 建议拆分为独立文件
- 多个 companion 文件主题高度相关？→ 建议合并为一个
- 地图文件列表遗漏新文件或包含已删文件？→ 建议更新

## Phase 2：提出重构方案

逐项展示，每项等待用户确认或拒绝后再进入下一项。

展示格式：

```
## 重构项 #N

**问题**: <用一句诊断性陈述概括>
**建议操作**: <拆分 | 合并 | 删除 | 迁移 | 压缩 | 更新引用>
**涉及文件**: <文件列表>
**具体方案**:
- <操作步骤 1>
- <操作步骤 2>
- <预计效果：AGENTS.md 从 XX 行降至 YY 行>
```

全部展示完后出示汇总表：

```
## 重构计划总览
| 操作 | 来源 | 目标 | 状态 |
|------|------|------|------|
| 拆分 | AGENTS.md §3 | conventions.md | 待确认 |
| 删除 | AGENTS.md §5 | (删除) | 待确认 |
| 合并 | deploy.md, ci.md | ci-deploy.md | 待确认 |
```

## Phase 3：执行

按风险从低到高依次执行，高风险操作需用户二次确认。

**执行顺序**：
1. 删除过期内容（git 历史可恢复，风险最低）
2. 压缩冗余段落（语义无损，风险较低）
3. 更新引用路径（需确保新旧路径都正确）
4. 文件内重组（移动段落，不改变文件边界）
5. 文件间移动/合并/拆分（改变边界，高风险，必须二次确认）

**每次操作后**展示 diff：行数变化、内容摘要。用户可即时回退。

## Phase 4：更新交叉引用

1. 更新 AGENTS.md 地图中的文件列表，确保字段完整
2. 确保所有 companion 文件间的互相引用路径正确（相对路径或绝对路径一致）
3. 确保 `.claude/CLAUDE.md -> .agents/AGENTS.md` 软链接存在且指向正确
4. 全局搜索被删文件名，清理所有残留引用

## 重构后审查

逐项对照检查：
- AGENTS.md 行数：目标 ~100 行，不超过 150
- 信息增量：不存在任何可从代码直接推导的内容
- 最小编码：每条指令都是最小必要表达，无废话
- 交叉引用：每个引用都指向存在的文件，无断链
- 软链接：`readlink -f .claude/CLAUDE.md` 指向 `.agents/AGENTS.md`

若审查不通过，标记问题项回到 Phase 2 重走。

## 反模式提醒

- 不要为"整洁"过度拆分导致碎片化（适得其反）
- 不要删除 TODO(harden) 标注的内容——保留不动或在硬化步骤中处理
- 不要大改后不做三原则审查——重构不是终点，可维护才是

## 生命周期提示

- 重构后发现内容缺口？→ 用 `/doc-harness-append` 补充
- 有约束已稳定且需要硬化？→ 用 `/doc-harness-harden` 转换
- 新项目还没文档？→ 用 `/doc-harness-init` 创建

## Edge Cases

- **用户不同意某项重构建议**：跳过该项，在汇总表标记为"已拒绝—待观察"，说明理由
- **AGENTS.md 空白但 companion 文件很多**：从 companion 文件反向生成地图（内容放在 companion，AGENTS.md 只做索引）
- **重构中发现新内容需求**：用列表记录，不在此次操作中处理，建议用 append 步骤单独进行
- **用户想撤销已执行的操作**：用 `git checkout <file>` 恢复，或 `git diff` 确认回退范围
- **伴侣文件大量且相互引用复杂**：先画依赖图再做操作，避免更新遗漏
